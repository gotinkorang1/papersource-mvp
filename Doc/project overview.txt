Yes — I would build **PaperSource as a premium Ghanaian office-supply commerce platform**, not simply a stationery catalogue with a cart.

The important architectural decision is this:

> **PaperSource has two purchasing paths living on the same product catalogue:**
> **Retail:** browse → cart → checkout → Paystack/MoMo → delivery
> **Business:** browse → quote basket → RFQ → PaperSource reviews/prices → customer accepts → order/payment → delivery

That distinction should influence the database, UX, admin dashboard, and Cursor instructions from day one.

## 1. PaperSource brand direction

### Brand position

I would position PaperSource as:

**“Ghana's modern workplace supply partner.”**

Not a cheap stationery shop. Not a school-bookstore aesthetic.

The feeling should be:

**Professional • Reliable • Organised • Modern • Efficient • Approachable**

The brand should be equally comfortable supplying:

* one notebook to an individual
* 20 boxes of A4 paper to an SME
* office setup supplies for a new company
* bulk stationery to a school
* recurring procurement for an organisation

### Visual concept

Use **paper, document grids, filing systems and office organisation** as the visual inspiration.

Avoid generic:

* giant floating pencils
* cartoon notebooks
* rainbow stationery
* obvious shopping-cart illustrations
* generic blue SaaS gradients

I would make the website look more like a **modern procurement catalogue/editorial design system**.

Think large typography, crisp grids, beautiful product photography, paper-like surfaces, subtle lines, tabs, labels and strong whitespace.

# 11. Very important money rule

Never store:

```text

```

as a floating-point price.

```text
7899
```

and format:

```text
GHS 78.99
```

This avoids rounding problems.

# 15. Payments for Ghana

Use **Paystack as the primary gateway**.

Support:

* cards
* Mobile Money
* payment links/hosted checkout where appropriate

Paystack specifically supports its Mobile Money payment channel for businesses in Ghana. Its documentation also notes that MoMo completes asynchronously, so the final payment result must be processed through the server/webhook rather than trusting the browser. ([Paystack][4])

Architecture:

```text
Customer
     ↓
Create Order
     ↓
Server
     ↓
Initialize Paystack
     ↓
Paystack Checkout
     ↓
MoMo / Card
     ↓
Webhook
     ↓
Verify payment
     ↓
Update Order → PAID
```

Never:

```javascript
if (url.includes("success")) {
   order.paid = true
}
```

The webhook/server verification must determine payment status.

# 30. Supabase

Supabase is an excellent fit here for:

* PostgreSQL
* Auth
* storage
* RLS
* database functions
* backups
* realtime features

But use it as PostgreSQL infrastructure — **not as a replacement for application architecture**.

Every exposed table should be protected properly by Row Level Security. Supabase specifically warns against treating mere authenticated access as authorization and recommends proper ownership/authorization policies. ([Supabase][5])

## Most important principle

Don't ask Cursor:

> “Build me a modern stationery ecommerce website.”

That is precisely how you end up with a generic AI-generated website.

Instead, we're going to give Cursor **PaperSource's product specification, architecture, design system, database model, business rules, security rules, quotation workflow, coding standards and testing requirements**. Cursor's current Agent Skills and project Rules are designed exactly for this type of persistent repository-level guidance. ([Cursor][14])

And I would lock the initial delivery rule as:

> **PaperSource provides direct delivery across Accra and Tema. Orders outside these areas are supported through nationwide delivery arranged on request.**

That should become a configurable rule in the database rather than simply text hard-coded into the homepage.

**The best next step is to create the PaperSource master product document for Cursor** — `PRODUCT.md` — covering every public page, user role, retail checkout, quotation/RFQ system, product catalogue, admin dashboard, database entities, design language, delivery logic and MVP acceptance criteria. That document can then become the source of truth Cursor follows throughout the entire build.
