# RLS and operations-admin implementation plan

**Goal:** Complete the MVP database policy baseline, then replace the delivery-zone, settings, customer, organisation, payment, and delivery admin placeholders with useful server-authorized screens.

**Constraints:** Preserve retail cart and quote basket separation. Keep money as integer pesewas and prices VAT-inclusive/server-authoritative. Staff authentication remains the signed local staff session for this milestone; all staff data access and mutations stay server-side behind the existing RBAC matrix.

## Milestone 1 — RLS hardening

1. Add a failing isolated-Supabase policy test covering public catalogue visibility, hidden draft children/inventory/private tables, authenticated ownership, organisation membership, and denied customer writes to server-authoritative commerce tables.
2. Add an idempotent `0009_rls_hardening.sql` migration that enables RLS on every public application table, replaces permissive catalogue child policies, removes direct inventory exposure, creates customer ownership/read policies, and narrows Data API grants.
3. Apply the full migration stack twice to the isolated local Supabase database and run the policy test.
4. Run the focused domain tests, typecheck, and lint; commit and push the RLS milestone.

## Milestone 2 — Settings and delivery-zone administration

1. Add tests for settings validation/defaults and delivery-zone validation/mutations before implementation.
2. Add a singleton settings table/migration and Drizzle schema. Store VAT as basis points, quote expiry as integer days, WhatsApp as an international number, and the public site URL as a URL.
3. Route tax calculations and quote expiry through server-side settings while retaining safe defaults if the settings row is unavailable during migration/development.
4. Implement `/admin/settings` and `/admin/delivery` pages plus same-origin POST handlers, with ADMIN/SUPER_ADMIN write authorization and Zod validation.
5. Verify database behavior, focused tests, typecheck, lint, build, and admin browser flows; commit and push.

## Milestone 3 — Useful staff reads

1. Add server-side query functions and focused tests for customers, organisations, payments, and deliveries.
2. Replace the four placeholder routes with dense, filterable/readable operational tables and RBAC gates.
3. Verify responsive admin rendering and role-denial behavior in the browser, then run the full quality suite.
4. Update `docs/ADMIN.md`, `docs/SECURITY.md`, and `docs/STATUS.md`; commit and push.

## Milestone 4 — Next MVP slice

After the admin/security milestone is green, continue to storefront zone-driven copy, remaining Product JSON-LD, Playwright stabilization, then Sentry. Quote-expiring email remains optional and comes last.
